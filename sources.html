Observation dates versus retrieval dates

Three timestamps travel with every snapshot: when the source observed it, when the collector retrieved it, and (for home collectors) when the hub received it. A recent retrieval never makes an old observation current.

Coverage grades, evidence and unknown coverage

Every map cell carries an activity count and, separately, a coverage grade with an evidence string. adequate: the collector observed throughout the window and the source documents coverage of that cell (source coverage can still be incomplete). partial: records observed; coverage incomplete — the count is not a total, and not a guaranteed minimum of real-world activity. unknown: nothing can be said about the cell. A cell with no outline has no records; that is not evidence of absence unless it was adequately observed. Comparisons (phase 3) will run only on adequate cells.

Search — what it covers and what it cannot

The Explore panel on World View searches only the records your browser has already loaded from each layer's latest published snapshot. It issues no request of any kind: no geocoder, no place-name dataset, no country boundaries, no history. It is not a search of the world, and not a search of everything a source holds.

LayerWhat a search can match
EarthquakesThe description text exactly as USGS writes it (for example "14 km SSW of Volcano, Hawaii"), and coordinates.
Fire detectionsCoordinates only — FIRMS publishes no name or description for a detection, so it is never text-searched.
ShipsVessel name and MMSI as received in the sample, and coordinates.
Forest disturbanceNothing. This layer publishes counts per cell and no individual records.
Kp, CO₂, sea iceNothing. These are indices, not records with places.

A place or country word matches text, not territory. Searching "Chile" finds loaded records whose description contains that word and misses records in Chile described some other way. Nothing in this box knows where a border is.

Coordinates are entered latitude first, then longitude — decimal degrees, with optional hemisphere letters (-33.92, 18.42 or 33.92S, 18.42E). Latitude is accepted from −90 to 90 and longitude from −180 to 180; a value outside its range is refused with the range named. A minus sign and a hemisphere letter together is ambiguous and is refused rather than guessed. When both values are in range, a latitude and longitude typed the wrong way round cannot be detected, which is why the order is stated at the input.

A coordinate search always offers to move the view to that position, whether or not any record is near it. It then separately lists loaded records within 250 km, nearest first, up to twelve with the true total stated. That radius is a choice made for this box: it is not a coverage boundary and says nothing about what was observed there.

"No matching loaded records" describes the loaded snapshot and nothing else. It does not establish absence. A layer that is hidden, whose state is unknown, or whose records are withheld by the records-and-cells pairing rule is not searched at all, and the panel names each one with the reason.

A result stays tied to what it was found under. Every result carries its layer and the collector run it came from. If that run is replaced, or the layer is hidden, or the layer's state lapses to unknown, or its records are withheld, the result is marked and refused rather than opened — the page never attaches an old record to a newer run. Each result is judged on its own layer, so one layer refreshing does not invalidate another's results. Nothing moves the view and nothing is selected without a click.
